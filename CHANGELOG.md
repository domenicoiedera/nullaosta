## [Unreleased]

### Added

- Receipt format, frozen before the engine was written: canonical action bytes
  (sorted keys, UTF-8, no insignificant whitespace) over
  `{action_class, target, params_digest, nonce, issued_at}`, with a per-attempt
  nonce generated by the gate so identical actions still hash differently.
- Policy engine: per action-class and per-domain `allow` / `deny` /
  `require-approval` in `policy.json`, defaulting to deny on the irreversible
  classes (pay, submit, delete, send, publish).
- Fail-closed approval gate: a gated action executes only with an approval bound
  to that action's canonical hash and unspent. No approval, a spent approval, an
  approver timeout or an unreachable approver all mean BLOCKED; there is no
  "continue anyway" path.
- Approval binding: the human approval signs the action's canonical hash, so a
  captured approval cannot be spent on a different action.
- Single-use approvals: a consumed-nonce ledger makes every approval single-use,
  closing approval replay and spent-nonce reuse.
- Key-trust split: three roles, three keys. The agent holds nothing, the tool
  signs receipts with a receipt key, the human approves with a separate approver
  key. `verify` asserts the approval principal is in `allowed_signers` and is not
  the executor identity.
- Seal-per-append receipt chain: every entry is sealed as it is written, so there
  is no unsealed tail; `verify` reports an unsealed file as UNSEALED, never clean.
- Independent verification: `verify` reconstructs everything from the receipt
  file plus public keys, exits nonzero on any tamper class (truncation, reorder,
  field edit, forged approval, swapped key, approval replay, unsealed file).
- Hash chain, SSH sign/verify, the fail-closed branch taxonomy and the
  falsification harness (each guard disabled in turn must turn a test RED, then
  GREEN again).
- CLI verbs: `init`, `check`, `approve`, `verify`, `log`. Library entry points:
  `decide()`, `seal()`, `verify()`.
- Test suite with tamper and mutation guards; CI matrix on
  ubuntu/macos/windows across Python 3.10-3.12.

### Provenance

The tool's outer shell (the hash chain with canonical bytes and head hashing,
SSH signing with independent verification, the fail-closed branch taxonomy and
judge-never-gates structure, and the falsification harness) was re-cut from the
author's earlier public MIT tool, `gatesmith` v0.3.0. The approval binding to
the action hash, the single-use/consumed-nonce semantics and the key-trust split
are new in nullaosta and did not exist in gatesmith.
